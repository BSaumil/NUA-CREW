# Android and iPhone acceptance record

No physical-device result is claimed by this checklist. For each row record Android/iPhone model, OS, build commit, tester, date and screenshot/video or issue reference. Use fictional candidate/employer data.

| Flow | Acceptance |
| --- | --- |
| Document wallet | PDF resume; PDF/JPEG/PNG certificate; camera permission denied/allowed; 4 MB boundary; invalid/unsafe file refused; scanner outage keeps upload unavailable; interrupted retry uses the same reservation; temporary download copies cleaned up |
| Consent and access | No attachment selected by default; employer sees only selected application documents; withdrawal/removal revokes access; another candidate/tenant cannot open a guessed document |
| Role and pay | Role search and award loading failure recover; changing award/classification clears confirmation; base references are distinct from assessed casual/penalty values; stale/below-minimum checks block saving/publishing |
| Overview and updates | Loading/error shows unavailable rather than zero; unread states survive relaunch; push opens candidate/employer destination; old-account deep links reveal no prior account data |
| Attendance | Check-in/out server time; venue-local correction while device is in another zone; repeated/skipped DST hour refused; employer approve/reject retains original; history shows each hours version |
| Offline recovery | Offline on upload/submit/read-state; no silent success; inputs retained on native errors; reconnect/retry refreshes state; double-tap does not create duplicate work |
| Accessibility | Small phone portrait; 200% text; keyboard does not hide controls; TalkBack/VoiceOver reads labels, errors and order; sheets focus/close correctly; empty-state buttons remain independently reachable |
| Session and privacy | Sign-out / account A→B clears all private query data; documents/history never persist in offline storage; biometric lock covers private screens before restore |

Capture both themes and both platforms. CI exports and browser emulation must be recorded separately from real-device evidence. Unresolved critical failures block the pilot.
